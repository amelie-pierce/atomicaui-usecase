# Adding use cases

Updated 2026-11-13: replaced the old single `registry.tsx` with the portable `src/usecase-gallery/` folder. Its own `README.md` is the how-to; this note holds the non-obvious facts.

- Discovery is `import.meta.glob` in `src/usecase-gallery/catalog/catalog.ts`; the rules and validation (id pattern, prefix match, duplicates) are in `src/usecase-gallery/catalog/build-catalog.ts`. A use case is a folder with `example.tsx` and `usecase.ts`; a component is `<component>.meta.ts`. No registry edit.
- Preview and code come from one file: `example.tsx` is rendered (lazy) and read with `?raw`; `src/usecase-gallery/catalog/snippet.ts` strips the kit import and the `Example` wrapper. It expects `return` to be the last statement of the component.
- `src/usecase-gallery/kit.ts` is the only file that imports the vendored kit (`src/vendor/atomic-aui`, read-only).
- Selection is the URL hash (`#Button-001`); unknown hash falls back to the first use case (`src/usecase-gallery/hooks/use-hash-selection.ts`).
- Layout: `Panels` (kit, wraps react-resizable-panels) above 840px, one stacked column below (`src/usecase-gallery/layout/layouts.tsx`, `usecase-gallery.tsx`).
- `vite.config.ts` enables `@vitejs/plugin-react`; without it JSX compiles with the classic transform and the page fails at runtime with "React is not defined" even though `npm run build` passes.
- Kit `Card` paints over bare children: put content in `Card.Body` / `Card.Content` (`src/usecase-gallery/ui/pane-card.tsx`), otherwise text is invisible.
- `Panels.Panel` styles land on RRP's nested inner div, which is a flex row by default; pane wrappers need `flex-direction: column` (`src/usecase-gallery/styles/gallery.scss`).
- The kit's `Icon` needs a Font Awesome web font; the kit resolves to FA 7 Pro Duotone (licensed, not installed). The shared Pro Web Font kit loads via one script tag in `index.html`; its deploy origin must be permitted. The tree chevron is the kit's own.
- Button props: only `aui` (`color`, `paint`, `scale`, `shape`), native `disabled`, and `Button.Icon` / `Button.Spinner` parts (`src/vendor/atomic-aui/lib/button/button.tsx`). There is no `loading` prop.
- All four panes share `PaneCard` (`src/usecase-gallery/ui/pane-card.tsx`, kit Card + Card.Content, no visible header; regions are named by `aria-label`, the tree keeps a visually hidden `h1`, and the Copy button lives in the code card content); typography is kit `Type` role `l3` (hcs body `sm`, 16/20) everywhere, one size for all text, weight only separating headings (table in the gallery README); `gallery.scss` sets only the root 16px / 1.35. Fonts: Inter and JetBrains Mono are self-hosted (`public/fonts`, `src/fonts.scss`) and `main.tsx` stamps `typeface="engineering" typography="body"` so kit tokens resolve. Verified in headless Chromium: both faces report `loaded`. Source of the sizes: hcs `prototype/App.tsx` and the kit `_110-typography.scss`.
- Tree disclosure: `TreePane` controls each component and area `Collapsible` (`open` state; choosing a use case reopens its component and area; closing never changes the hash). Arrow keys move over toggles and links. The selected link has no accent bar: primary text (orange-600 via the scoped `--theme-primary`) on an 8% `color-mix` primary tint (9% on hover), plus bold `Type`. The docs header is one `h2` with the id and title inline (see Area badges below).
- Button use cases mirror the real hcs app (hcs commit `bb0f21f1`) and were regrouped by area on 2026-11-15 (ids changed; 014 -> 016 use cases). Old -> new: 001+002->001 (Dialog footer), 003->002, 004->004 (Previous/Next) and 005 (End), 005 and 006's Reset filters->007, 006's Try again->016, 007->013, 008->014, 009->010, 010->008, 011->011/012/003, 012->009, 013->015, 014->006; each `where` cites its hcs ids. Brand atomic naming trap: `secondary` is black, `surface-alt` is gray, `primary` is orange. Icon-button cases need `IconButton`, which `src/usecase-gallery/kit.ts` re-exports.
- Button icons mirror hcs (updated 2026-11-14): glyph names only, no `layer`/`weight`/`family` props (the provider default is classic duotone) and no per-icon colour; the host button's profile sets the size unless the real site pins one (many cases keep `aui` scale `sm`). Text-only roles (001, 014, 016) get no glyph; 007 shows Print Output with `print` and View options without. 008 shows the closed `angle-right`; the app rotates it 90 degrees through CSS when `aria-expanded` is true.

- Area badges: `src/usecase-gallery/apps.ts` is the one app registry (key, name, label, url); a use case lists keys in `apps`. Badges are kit `Chip` inside a `target="_blank" rel="noopener noreferrer"` link. The docs header puts id and name in one `h2`, the id on its own line and the name below it (a long name wraps).
- Headless check: `chrome-devtools-axi` could not launch its own Chrome here; start puppeteer's Chrome with `--headless=new --no-sandbox --remote-debugging-port=<p>` (see `~/.cache/chrome-libs/axi-env.sh`) and point `CHROME_DEVTOOLS_AXI_BROWSER_URL` at it, with your own session and port.
- In-context preview: `src/usecase-gallery/contexts/<area-slug>.tsx` (one per area, discovered by glob in `catalog/catalog.ts`) wraps the example in a real kit area; `catalog/snippet.ts` `toContextSnippet` splices the example into the context's `{children}` line for the code pane. The toggle is kit `ToggleGroup` in `ui/render-pane.tsx`, mode state in `layout/usecase-gallery.tsx`. Gotchas: Base UI Dialog.Popup throws without `Dialog.Portal`, so contexts portal into the stage (`container={host}`) and omit Backdrop/Viewport; `Popover.Popup` is unstyled (wrap a `Card`) and its positioner is forced static in `gallery.scss`; keep the stage div outside `Suspense` or its ref loops. A use case whose control sits elsewhere than its area's other controls sets `contextVariant` in `usecase.ts` and gets `contexts/<area-slug>-<variant>.tsx` (done for the walkthrough and popover close X, top right of the card header; `build-catalog.ts` fails if the file is missing). Chrome-devtools-axi bridge can be stuck; drive Playwright's chromium over CDP instead.

- Dialog and walkthrough contexts rebuilt from the real hcs containers (2026-11-16): the Button-001 dialog scenes (now `usecases/button/Button-001/scenes/`, `contexts/dialog.tsx` was removed) are a non-modal Dialog Reset scene (children = footer; the vendored AlertDialog is forced modal, so it is not used) plus static licence (Accept disabled) and feedback stand-ins; `contexts/walkthrough.tsx`, `walkthrough-last.tsx` (`contextVariant: 'last'`) and `walkthrough-close.tsx` build the 328px `View` card with the counter pushed by an inline `marginInlineStart: auto` and the X in the corner by inline position (kit sx has width tokens only up to 384 and no inset axis). The stage uses `align-items: safe center` so tall scenes scroll, and dialog popups are capped to the stage width on narrow screens. Sizes are token-derived, unverified. Remaining mismatches for other areas live in the hcs contexts report (parts 2 and 3).

- In context scenes rebuilt from the hcs containers, parts 2 and 3 (2026-11-16, branch `fm/usecase-ctx-pane-table`): Output header (`scenes/` of Button-007 Enabled/Disabled, `contexts/output-header-helpers.tsx` for the scroll helpers), Toolbar, Table (row expander, header `actions` kebab), Panel header and rail, Form (Beam Properties, label help trigger), Body text, Popover footer and help, Viewer (Reset view, View options). Ids added: Button-017 Reset filters, 018 field help trigger, 019 View options (007 and 010 changed area to `Output header`; 007 now only Print Output; 008, 011, 012 examples became single buttons because the context has one slot per example). Sizes are token-derived, unverified. Facts: use cases with several scenes declare `cases` in `usecase.ts` and `scenes/<id>.tsx` (README "Several cases"); sample content lives in `src/usecase-gallery/mock-data.tsx` and `<Mock... />` tags become one-line comments in the copied code (`catalog/snippet.ts`); `Dialog.Description` is a `<p>`, so do not nest a `Type as="p"` in it; the stage now scrolls (`min-block-size: 0; overflow: auto`) so the toggle and case picker stay in view; `Radio`/`Checkbox`/`Switch` labels need the `.Label` part, bare children render nothing. Framed stand-ins (not buildable from kit parts): the 3D canvas, the view cube, the viewer overlay position and the popover/menu positioning (shown static).

- Per-app In context UI (2026-11-16): a case may set `app` (an `apps.ts` key); `catalog/app-views.ts` `appsWithUi` / `casesForApp` feed a kit `ToggleGroup` row in `ui/render-pane.tsx`, shown only when two or more apps have cases (no use case has one yet, so the gallery looks unchanged). `source` records the source design path per app. The agent procedure is the project skill `.claude/skills/usecase-gallery/SKILL.md`.
